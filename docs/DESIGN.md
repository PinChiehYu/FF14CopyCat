# 網頁使用流程與設計

本文件描述 FF14 CopyCat 網頁**給使用者的樣子**：使用流程、各區塊呈現什麼、如何操作、判定規則，以及待辦事項與設計變更紀錄。架構、程式實作、資料處理、驗證數據與部署見 [TECH_NOTES.md](TECH_NOTES.md)。

網站：https://pinchiehyu.github.io/FF14CopyCat/

## 網站目標

讓玩家把自己的 FFLogs 日誌與前輩的日誌並排比較，依 Boss 機制對齊兩場戰鬥，找出技能循環、減傷、走位與站位上的差異，並給出具體的改進建議。訪客不需要 FFLogs 帳號，貼上連結即可使用。

## 使用流程

輸入的兩個連結保存在本頁網址（`?mine=…&ref=…`），重新整理後自動還原，也可以直接把網址分享給別人。選好戰鬥與角色後，保存的連結會換成帶有該戰鬥與角色的連結（`?fight=…&source=…`），還原時不用重選；清空輸入框時一併移除。比較結果標題右側有「複製分享連結」按鈕：依目前兩邊的戰鬥與角色產生連結並複製，按鈕短暫顯示「已複製」；瀏覽器拒絕自動複製時以對話框顯示連結讓使用者手動複製。

### 從繁中服排名找參考日誌
參考日誌標題列右側有「搜尋前輩日誌」按鈕（放大鏡圖示、實心強調色，大小與標題列同高；選好我的日誌前停用，滑鼠提示說明原因），按下後在輸入框上方浮出面板，不推擠下方的戰鬥／角色欄位，兩邊日誌框的欄位保持對齊；點面板外或按 Esc 關閉（選單開著時 Esc 先關選單），搜尋結果保留：
- **範圍**：只找繁中服（泰坦、奧汀、利維坦、迦樓羅、伊弗利特、鳳凰、巴哈姆特）與我同一個 Boss、同難度、同職業的擊殺。FFLogs 不替繁中服排名，所以排名由本站自建：定時掃描 FFLogs 上的公開報告，收錄繁中服玩家的擊殺。私人報告不會收錄，資料需要時間累積。
- **PR**：**每一場擊殺各自計算**（與 FFLogs 相同）：把這一場的 **rDPS** 和其他玩家（名稱＋伺服器）各自最好的一場比較，只和同 Boss、同難度、**同職業**的繁中服玩家比較（其他職業不列入人數與名次；同一人玩其他職業也分開計算）；PR＝勝過多少比例的玩家（比這一場好的玩家數＋1 為第一名時 100、最後一名 0），人數為有紀錄的玩家數。選項的名次（#）為這一場在所有場次（重複上傳只算一次）中依 rDPS 的順位，PR 相同的場次 rDPS 仍不同，名次不重複。rDPS 取自 FFLogs 傷害表（繁中服日誌不排名，但 FFLogs 仍計算 rDPS），把隊友 Buff 的加成歸給給 Buff 的人，比 DPS 更能反映個人表現；但只和繁中服玩家比較，與 FFLogs 網站上國際服的 PR 仍不能直接比較。**PR 在範圍內的每一場都列出**（同一人可有多場，每場標示名次、自己的 PR 與 rDPS）：好的玩家常有多場好紀錄，只列最好的一場時，那一場的隨機機制常與我的不同而無法對齊；同一人較差的一場則依它自己的 PR 決定是否列出。同一場戰鬥被不同人重複上傳（同一位玩家、戰鬥的實際開始時間相同）只留一筆。收錄後被上傳者設為私人或刪除的報告會打不開，每天確認一次並從排名移除。
- **設定與結果**：輸入 PR 範圍（欄位標示為「武士 PR」等職業名稱，旁邊的「?」說明只在該職業間計算與預設值；**預設比我這場的繁中服 PR 高一段**：我的 PR＋1～＋20（上限 100，例 PR 40 → 41～60、PR 85 → 86～100），找輸出與打法比我好一些、較好模仿的前輩；我的這場沒有 PR（未擊殺或沒有排名資料）時 90～100；手動改過就沿用，換了我的日誌再回到預設；下限不能高於上限，超出時離開輸入框會自動調回範圍內）後按「搜尋」，命中的紀錄（最多 40 筆，依 rDPS 由高到低）放在下拉選單中，每個選項為名次、PR、「玩家 @ 伺服器」、rDPS、戰鬥長度，日期在滑鼠提示（手機寬度只顯示 PR、玩家、rDPS 數字）。選單上方一行「共 N 人，列出 M 筆」，完整說明（每場各自計算 PR、列出範圍內的所有場次、依 rDPS 排序）放在滑鼠提示，避免撐高輸入框。從選單選一筆就填入參考日誌（帶有該場戰鬥與角色）並關閉面板，選單保留顯示目前選的紀錄；重新搜尋或換了我的日誌時清空。
- **機制相同**（勾選框，滑鼠提示說明用途）：勾選後逐筆抓 Boss 施放、依時間軸對齊後與我比對，每個選項最後標示「機制相同」或「N 處不同」（只算同一時間施放不同技能的隨機變化，「只有一邊」多半是輸出差異造成，不算），並隱藏不同的。搜尋與逐筆比對期間，結果區只顯示轉圈與「搜尋中…」／「比對機制中…」（與完成後同高，面板不跳動），PR 範圍、機制相同與搜尋按鈕都停用；全部完成後才一次顯示結果，筆數不會隨比對進度跳動。只比對主要機制（同「Boss 機制差異」），「N 處不同」是**同一時間點有幾處不同**（同一時間多個機制不同算一處，同一招連續結算也算一處），滑鼠提示逐行列出每處的時間（該筆紀錄的戰鬥時間）與不同的機制。隨機機制多的 Boss（例如呼嘯之劍）很難有完全相同的：全部比對完仍沒有時，改為依不同處由少到多列出，並在摘要列註明「無完全相同，依差異排序」。
- **比對的機制**（比對完成後出現在搜尋列下方，預設收合，摘要「比對的機制（勾選數／總數）」）：列出這次比對中至少一筆與我不同的主要機制（繁中服名稱；名稱相同的機制合併為一項，例如圓形與扇形的「群狼劍」），滑鼠提示為與我不同的紀錄數。取消勾選不在意的機制（例如呼嘯之劍的「摧枯拉朽」），「機制相同」與排序就只看勾選的機制；取消勾選的機制依 Boss 記在瀏覽器中。

1. **貼上兩個 FFLogs 報告連結**：左邊是「我的日誌」，右邊是「參考日誌（前輩）」。連結中的 `fight`、`source` 參數會被用來預選戰鬥與角色；輸入過程會等使用者停止輸入約 0.4 秒後才載入。
2. **選擇戰鬥與角色**：每份報告顯示戰鬥下拉選單（每列為 `#編號`、Boss 繁中名稱、戰鬥長度、擊殺／滅團徽章（綠／紅），各欄固定寬度、上下對齊，Boss 名稱與角色名稱的起點也對齊；滑鼠停留顯示英文名稱）與角色下拉選單（位置、「角色名 @ 伺服器」〔與前輩日誌搜尋清單相同，伺服器以較小的灰字顯示〕與職業繁中名稱徽章，徽章依職能上色：坦克藍、治療綠、輸出紅；不含極限技等假角色）。角色依隊伍位置排序：坦克 → 純治療（白魔、占星）→ 護盾治療（學者、賢者）→ 近戰 → 遠程物理 → 魔法，同組依職業名稱；標準的 2 坦 2 補 4 輸出隊伍會在名字前標上 MT／ST／H1／H2／D1～D4；**MT／ST 依實際坦 Boss 的情況**：承受 Boss 普通攻擊傷害較多的坦克為 MT（資料查到前坦克先不標位置），組成不標準時不標位置。參考日誌只列同職業時，位置仍依整隊判斷。下拉選單為自訂元件，可用滑鼠或鍵盤（上下鍵、Enter、Esc）操作。不顯示報告標題。選擇的優先順序：
   1. 使用者在下拉選單的手動選擇（換戰鬥時角色回到自動選擇）。
   2. 連結中的 `fight`、`source`。
   3. **參考日誌依「我的日誌」自動選擇**：戰鬥選單**只列與我同一個 Boss 的場次**，預設選最後一次擊殺（沒有擊殺則選最後一場）；連結指定的場次不是同一個 Boss 時不採用。報告中沒有同一個 Boss 時，戰鬥與角色選單都顯示「這份報告沒有 X」並停用（與沒有同職業時相同）。角色選單只列出該戰鬥中與我同職業者——**恰好一位時自動選取並鎖定**（選單右側以鎖頭圖示取代箭頭，滑鼠提示說明原因，文字與顏色維持正常不淡化，不能改選，也不受參考連結的 source 影響）；兩位以上時選單上顯示「這場戰鬥有 N 位 X，請選擇要比較的對象」，由使用者在其中選擇（連結的 source 是其中一位時預選）；沒有時**選單本身顯示「這場戰鬥沒有 X」並停用**。提示都顯示在選單上，不另外加說明列，避免版面變長。
   4. 都沒有時：戰鬥選最後一場，角色不選。

   目的：使用者通常只要貼上前輩的報告連結，其餘自動完成。
3. **選好我的日誌就先顯示分析（同一頁漸進顯示）**：標題為「我的分析」，只用我的日誌能做的分析先顯示（見下方「只選了我的日誌」）；選了參考日誌後標題換成「比較結果」、補上比較。兩邊分開載入，我的日誌載入過就不重抓，換參考日誌時我的分析立即顯示，摘要下方標示「載入參考日誌中…」。
4. **檢查是否可比較**：兩場必須是同一個 Boss、同一職業，否則在摘要下方顯示原因（例如「兩位玩家的職業不同（毒蛇劍士 / 武士）」），其餘仍顯示我的分析。
5. **顯示比較結果**：依序顯示下列區塊。技能名稱先以英文顯示，繁中名稱查到後自動替換。「複製分享連結」只在有參考日誌時顯示。

## 比較結果頁面

區塊或表格列的說明（計算方式、名詞解釋）不佔整行，也不藏在資料文字的滑鼠提示裡，而是放在標題或列名旁的「?」圖示：滑鼠停留顯示提示，點擊（手機）展開說明框，點其他地方或按 Esc 收起。目前用在摘要表格的列名、GCD、少打 GCD 的時段／停手時段、技能使用次數、站位摘要與時間軸工具列。說明框超出畫面右緣時往左移。

### 只選了我的日誌
區塊與順序和比較結果相同，需要參考才有意義的部分不顯示；摘要下方一行提示「選擇參考日誌後可比較時間軸、站位、機制與技能時機」。
- **摘要**：只有「我」一欄；不列比較範圍（整場都列入統計）；開打前列出全部效果。
- **建議**：只用規則判斷的建議（見「建議規則／只有我的日誌時」）。
- **技能窗口**、**DoT**：只有我的一欄（依我的版本評分）。
- **Boss 機制差異**：不顯示；也不顯示對齊說明列。
- **GCD**：只有我的 GCD 數、間隔與空檔。「少打 GCD 的時段」改為「**停手時段**」：GCD 間隔超過門檻（同少打 GCD 的時段）、扣掉 Boss 無法選中與死亡的時間後仍超過門檻的時段，每列為「時間區間｜停手 X 秒｜約少 N 個 GCD」（依我的 GCD 間隔估計：扣除後的長度扣掉一個正常 GCD 還能多打幾個）；控場的標示相同。
- **技能使用次數**：只有我的次數；冷卻技卡片只有我的「用了／最多可用」與晚用。
- **站位與當下狀態**：沒有摘要、距離圖與站位差異卡片（手機沒有「站位差異」分頁）；俯視圖只有「場地」（北方朝上，照實際位置畫我與 Boss）與「以 Boss 為中心」兩種視角，Boss 以橘框標示「Boss」；當下狀態只有我與 Boss。
- **時間軸**：以我的戰鬥時間為橫軸，只有 Boss 與我的技能列。

### 摘要
- 以**表格**並列「我」與「參考」兩欄（欄標題以橘／藍區分），只列上方選單沒有的資訊：
  - **版本**：依戰鬥日期對照繁中服版本上線日期判斷的遊戲版本，例如「7.2」「7.25」（本工具只處理繁中服日誌）；兩邊不同時文字變色。技能窗口規則移植自 xivanalysis（依國際服版本撰寫），繁中服版本對應到國際服版本選用規則：繁中服 7.0～7.15 的職業技能等同國際服 7.2、7.2 起等同國際服 7.3。兩邊版本不同、且有技能窗口規則因此不同時，表格下方列出「兩邊版本不同，技能窗口依各自版本的規則評分：無情（我 …／參考 …）」。
  - **rDPS**（第二列）：兩邊整場的 rDPS（FFLogs 計算；繁中服日誌不排名但仍有計算），我比參考少時以紅字標出差距「−N」；「?」說明 rDPS＝DPS − 隊友 Buff 加成 ＋ 自己 Buff 貢獻，數字的滑鼠提示為該場的各項數值與 aDPS。
  - **繁中服 PR**（第三列）：這場的 rDPS 在本站繁中服排名中的 PR，計算同「從繁中服排名找參考日誌」（與同職業其他玩家各自最好的一場比較；自己已在排名中時不和自己的最好一場比較，所以與排名表上同一場的 PR 相同；不在資料庫中的日誌也能算）。「?」說明計算方式與比較的人數。未擊殺或沒有該職業的排名資料時「—」。
  - **死亡**（第一列，重點標示）：列出每次死亡的時間與致命技能（紅色標籤），點擊跳到該時間；沒有死亡時只顯示「—」。
  - **比較範圍**：一定從 0:00 開始，不顯示起點。較長一方顯示「到 結束點 −N.Ns」（各自的時間；被裁掉的秒數以短標示，說明在「?」，手機上不換行），沒被裁切的一方只顯示「全場」（戰鬥長度已在選單上）。
  - **開打前**：開打當下身上已有的自身效果（例如武士的明鏡止水、天道、真北，騎士的鋼鐵信念、進食），推知開打前用過的技能。「食物效果時間延長」（含部隊特效版）只延長食物時間、不影響戰鬥，開打前、當下狀態與比較都不顯示。每邊只列對方沒有的效果（橘色），兩邊都有的列在「?」的說明裡；沒有可列時，兩邊完全相同顯示「相同」，否則顯示「—」。FFLogs 沒有開打前的施放紀錄，所以沒有確切時間，也看不到開打時已經消失的效果。
  - 玩家、職業、戰鬥、擊殺／滅團與戰鬥長度已在上方的選單顯示，不重複列出。
- 表格下方一行說明對齊錨點數與兩場的時間差範圍；有推進差距時接著列出「推進差距：6:31.2 我慢 8.9 秒」（紅色，我較快時為綠色「我快」），點擊跳到該處，滑鼠提示說明。錨點少於 5 個時提示對齊可能不準。
- 沒有職業規則的職業（目前只有青魔道士等非戰鬥職業）提示不區分 GCD／oGCD。

### 建議
依重要性分成「優先」「建議」「參考」三個**分頁**（分頁標籤顯示則數，紅／橘／灰區分），預設顯示最高一級，沒有內容的分頁不顯示，避免頁面過長。每則有標題與說明；可定位到時間點的建議有「查看」按鈕，會移動時間游標並把時間軸捲動到該處。規則見下方「建議規則」。

### 技能窗口
依職業規則（移植自 xivanalysis）檢查「某個效果期間應該做到的事」，兩邊各自評分後並排比較；沒有規則的職業不顯示這一區。
- 表格每列一種窗口（圖示與名稱），「我」「參考」兩欄各顯示「合格數/評分數」與每個窗口的時間標籤：綠色合格、紅色有問題、灰色不評分（到比較範圍結束都還沒結束，也就是另一邊的戰鬥先結束、這一邊其實還在打）。被自己這場的擊殺截斷的窗口照常評分但放寬要求，滑鼠提示註明「戰鬥結束前的窗口，要求依剩餘時間降低」。滑鼠停留顯示時段與問題，點擊跳到時間軸（我的時間換算成參考時間）。
- 窗口名稱與問題說明一律用官方繁中名稱：效果名稱、「技能 後 N 秒」（技能觸發的固定時長窗口；技能窗口表格的名稱欄只顯示技能名稱與小字秒數，例如「武神槍 20秒」，完整說明在滑鼠提示，避免名稱欄換行）或「效果＋效果＋效果」（多個效果同時存在的期間）。問題例如「只打了 7 個 GCD（應 8 個）」「缺少：調停」「碎心箭、死亡箭雨 合計只用了 2 次（應 3 次）」「不應使用：強甲破點突」。
- 時間軸上，每側 GCD 列的底部以同樣顏色的細條標出窗口期間。
- 判定共通規則：
  - 依時間結束的窗口，應打的 GCD 數以窗口長度封頂（窗口 − 0.25 秒能放進幾個 GCD）；依層數結束的（例如明鏡止水）不封頂。

### DoT
有 DoT 的職業（移植自 xivanalysis 各職業的 DoT 模組）顯示這一區，每條 DoT 一列：名稱（單體與範圍版合併為一列，例如「高階雷電／高階中雷電」）與小字「目標 N%」，「我」「參考」兩欄各為「覆蓋 N% · 提早 N 秒／分」。說明在標題旁的「?」。

### Boss 機制差異
表格只列**主要機制**（玩家需要處理的攻擊，取自 cactbot 的零式時間軸），不列輔助判定、連續攻擊的每一下等；沒有 cactbot 資料的 Boss 列出所有低頻技能。技能名稱一律用繁中服名稱。表格上方只寫「共 N 處不同」，表格列出兩場 Boss 機制不同的時間點（參考時間，可點擊跳轉）、類型（不同變化／不同版本〔兩邊名稱相同、技能 ID 不同，例如方向不同〕／只有我／只有參考）與兩邊的 Boss 技能。只在一邊日誌中有施放紀錄的敵人（例如只被一邊記錄到的雜兵）不列入。主要機制的來源、類型的意義、「站位或走位差異可能是機制造成」與「推進造成的只有一邊不列出」等說明放在標題旁的「?」。顯示盡量簡化：
- 同一次攻擊由多個同名技能 ID 組成時（例如熱舞綠光的「四連指向、定格＆播放」同時有 4 個 ID），名稱只顯示一次。
- 同一招的連續結算（兩邊技能名稱與類型相同、間隔 6 秒內）合併成一列，只顯示第一個時間點，不註明範圍或次數。

### GCD 概況與少打 GCD 的時段
- 表格：GCD 數、GCD 間隔、空檔總計（我／參考／差距）。GCD 比參考慢 10 毫秒以上時提示可能是技能速度或加速效果的差異。說明空檔含 Boss 無法攻擊的時間，與參考的差距才有意義。
- 「少打 GCD 的時段」清單：每段一列、欄位對齊：`我的時間區間｜停手 X 秒｜參考打 N 個 GCD`（手機上也不換行）；參考打 3 個以上 GCD 的時段左側色條與數字為紅色。停手期間我被 Boss 控場時，該列左側色條為紫色並加上「控場」標籤（滑鼠提示列出控場效果），清單上方註明「其中 N 段你被 Boss 控場，停手是機制造成」。點時間跳到時間軸；時間軸上以紅色區塊標示。

第一個分頁為**冷卻技**（冷卻技是否好了就用，移植自 xivanalysis 各職業的 CooldownDowntime）：每個追蹤的冷卻技一張卡片，顯示我／參考的「用了／最多可用」、我的晚用次數（冷卻好後晚 5 秒以上才用）與最晚的一次；滑鼠提示列出每次晚用的時間（參考時間）。「最多可用」從開場預期的第一次使用起、每次冷卻好就用計算（含充能、會縮短冷卻的技能），Boss 無法選取（沒有位置）的時段不算浪費；開打當下身上有同名效果（例如開打前的明鏡止水）視為開打前用了一次；實際次數超過上限時以實際次數為上限。冷卻時間與充能依遊戲版本（例如血壤 7.4 起 60 秒）。

### 並排時間軸
- 橫軸為參考日誌的時間，可縮放（10、20、40、80 px/秒）。一方推進較慢時（推進差距），兩邊在這段各自照實際長度排開，較快的一方在推進後補上同樣長度的空白（斜線，滑鼠停留說明是誰多花的時間），較慢一方的施放不會擠在一起；推進之後兩邊再接回同一個位置。
- 列：時間尺、Boss（參考；對齊錨點以紫色標示；推進差距以「我慢／快 N 秒」標籤標在參考推進的時間點）、參考 GCD、參考 oGCD、我 GCD、我 oGCD（我的施放已依 Boss 機制對齊）。
- 技能以圖示呈現；滑鼠停留顯示「繁中名稱（英文） 原始時間（對齊後時間）」。
- 標示：Boss 無法選中的時段（灰底，兩邊各自依自己的日誌標示；例如呼嘯之劍召喚光狼、殘影劍、轉場，滑鼠停留顯示起訖時間。只寫「Boss 無法選中」，不附機制名稱：現有資料無法推知哪個機制會造成無法選中）、死亡（每側第一列的紅色 ✕，死亡到恢復行動之間畫紅色斜線；滑鼠停留顯示致命技能）、少打 GCD 的時段（紅色區塊）、我的戰鬥較短時的結束線（紅線）、比較範圍外（虛線與半透明遮罩，標示「比較範圍外」）、共用時間游標（紫線）。點擊時間尺可移動游標。

## 比較規則

- **時間軸對齊**：兩場戰鬥的擊殺時間、轉場時間（依輸出推進）與隨機機制的順序都可能不同，因此不以絕對時間比較，而是以 Boss 的技能施放為錨點，把「我」的時間換算成參考日誌中「同一個機制」的時間。所有比較都以參考時間呈現。原則是**兩場從 0 同時開始，同一個機制在兩邊的時間差只會在推進（依血量的轉場）時改變**：
  1. **只看兩邊都有記錄的敵人**：同一場戰鬥，雜兵的施放可能只被其中一份日誌記錄（例如熱舞綠光的青蛙舞者），這些施放不比較。
  2. **依時間配對**：同一個技能在兩邊的施放，從 0 開始依時間配對，取「時間差最穩定」的一串作為錨點。時間軸固定的戰鬥（熱舞綠光）時間差一直接近 0；依血量推進的戰鬥（呼嘯之劍）推進後時間差跳一次、之後維持。密集的連續施放（例如隨機方向的連續衝刺）不會為了多對上幾個而整段挪動。
  3. **隨機機制視為同一機制**：兩場在同一時間點施放的不同變化（熱舞綠光的放入 A 面／B 面、二連／三連／四連指向、4 拍／8 拍節奏，呼嘯之劍 Hero's Blow 的左右等）歸成同一組，我的「放入 A 面」就會配到參考同一時間的「放入 B 面」。有 cactbot 資料的 Boss 直接以 cactbot 時間軸的分組（同一條目的不同版本）為準，從一開始就當成同一機制；另外再加上兩場比較找出的組。只有一邊施放的機制（例如輸出夠高時被跳過的空間斬）不算同一組。
  4. 錨點之間依時間比例換算，最後一個錨點之後照原速延伸。轉場後的機制重新以錨點對齊，轉場前的差距不會延續放大。
  - 遊戲資料沒有名稱的 Boss 技能（例如熱舞綠光機制前的演出動作）也用來對齊，但不顯示。
  - 目前的實測：熱舞綠光五組比較的時間差都在 1.5 秒內；呼嘯之劍的轉場差距（6.7～11.3 秒）正確保留。- **比較範圍**：所有統計（GCD、少打 GCD 的時段、技能使用次數、站位、建議）只計算兩場都在進行的時段；較長一方超出的部分沒有比較對象，不列入統計，但時間軸仍完整顯示並標示範圍外。Boss 機制差異只列到較短一方結束。
- **施放時間**：有詠唱條的技能以「開始詠唱」的時間計，被打斷的詠唱不計。
- **GCD**：以遊戲的公共冷卻判定（含舞步、結印等較短的 GCD，以及會觸發公共冷卻的能力如 Meditate）。GCD 間隔取中位數，**上限 2.5 秒**（GCD 最長 2.5 秒）。
- **少打 GCD**：我停手超過 1.5 倍 GCD（且至少多 1 秒）、而參考在同一段（對齊後）仍施放 GCD 時才算；雙方都停手的時段（Boss 無法攻擊等）不算。\n- **Boss 強制控場**：Boss 施加在玩家身上、1～10 秒、**在兩場的每一次期間內都沒有開始任何 GCD** 的 debuff 視為控場（例如熱舞綠光的「完美收尾」；「蹦迪」、魔法受傷加重等期間仍能施放，不算）。少打 GCD 的時段與我的控場重疊至少 1 秒時標示為控場，不列入停手建議。兩邊同時被控場時參考也停手，本來就不算少打。遊戲資料沒有控場分類、名稱也看不出來，因此由日誌判斷。
- **平均時機**：同一技能兩邊的使用依時間順序配對（相距 30 秒以內才算同一次，可跳過多出的使用），計算我平均早或晚多少；使用 30 次以上的技能（連擊等）不計算。
- **站位**：見下方「站位判定」。
- **Boss 機制差異**：對齊後比較兩場的 Boss 主要機制（cactbot 時間軸列出的技能；沒有資料的 Boss 比較所有低頻技能，自動攻擊等頻繁的技能不比較；只看兩邊都有記錄的敵人）。主要機制只在一邊出現、但另一邊同一時間有 cactbot 未列的施放時（同一招的另一個版本，例如三連指向比二連多一下），不列為「只有一邊」。同一技能在另一邊相差 5 秒內視為同一次機制（一對一、時間最近的先配：連續多下的機制只有第一下版本不同時，不會配到另一邊的下一下；另一邊同一時間有同一機制的其他版本時，視為同一時間的不同版本，不跨到下一下配同一版本，例如放縱勁舞每下方向隨機）；其餘同一時間（1.5 秒內）兩邊施放不同的技能 → 不同變化（隨機機制；兩邊名稱相同、技能 ID 不同時為「不同版本」，例如方向不同）；只有一邊施放 → 只有我／只有參考。推進差距的時段內只有一邊的施放（例如推進較慢的一方在轉場前多一次空間斬）是推進時間不同造成的，不列出。同一招連續結算的多個時間點合併成一列。

### 站位判定

站位判定用於距離圖、站位差異卡片、摘要與建議，不隨俯視圖的視角改變。所有時間為參考時間（我的時間依對齊換算）。

**位置資料**
- 玩家：玩家自己的日誌事件（施放、受傷、治療等）帶有座標，約每 0.4 秒一筆；相鄰兩筆相隔 4 秒內以直線內插，相隔更久時只在兩端 1 秒內沿用最近一筆，其餘視為沒有位置（例如轉場期間沒有事件）。
- Boss：Boss 本體（subType 為 Boss 的角色）的座標與面向；取樣較稀疏，相隔 30 秒內內插、最多沿用 10 秒；面向只沿用前後 5 秒內的取樣。

**判定用的距離**（每 0.5 秒取樣）
- 兩場 Boss 在同一處（相距 8 yalm 內），或任一邊沒有 Boss 位置或面向時：兩人**在場地上的距離**。
- 兩場 Boss 站在不同位置（相距超過 8 yalm，例如 M7S 第二階段 Boss 隨機站在左右平台、M6S Boss 衝鋒）：場地上的距離沒有意義——兩人都站在各自 Boss 正面時場地上可能相距很遠，反之場地上靠在一起時相對於 Boss 可能完全不同。改用**以各自 Boss 為基準的距離**：兩人各自換算成相對於自己那一場 Boss 的位置（Boss 在原點、面向朝上，同俯視圖「以 Boss 為中心」），再算兩點距離。稱為「以 Boss 為基準」。
- 只平移、不依面向旋轉（「對齊 Boss」視角）不能用於判定：兩場 Boss 面向相反時，兩人都站在 Boss 正面反而會在相反兩側（M7S 第二階段：場地上約 20 yalm、平移後約 40 yalm、依面向旋轉後 2～4 yalm）。

**站位差異**
- 判定用的距離超過 8 yalm、持續至少 2 秒；間隔 2 秒內的相鄰段合併。最遠距離為段內判定用距離的最大值。
- 段內過半取樣以 Boss 為基準時，這段標「以 Boss 為基準」。

**段的屬性**
- **機制不同**：段期間或開始前 10 秒內，兩邊在同一時間施放不同的 Boss 技能（「Boss 機制差異」的不同變化）。
- **Boss 無法選中**：與任一邊 Boss 無法選中的時段（所有 Boss 都無法選中 1 秒以上）重疊。轉場時玩家常被強制移動、落地後無法移動；日誌沒有「無法移動」的狀態，位置取樣也稀疏，無法判斷哪一段是玩家能控制的。
- **可能是對稱站位**：把參考的位置做左右、前後或點對稱後與我接近（6 yalm 內，且不到原距離一半），且同一種對稱能解釋段內過半的時間。場地判定時以參考的 Boss 或場地中心（參考 Boss 位置的中位數）為中心；以 Boss 為基準時以 Boss 為中心，左右／前後為 Boss 的左右／前後。
- **結算的機制**：兩邊的 Boss 施放各自整理（同一技能 1 秒內只算一次，整場施放超過 8 次的技能如自動攻擊不算），施放完成的時間落在段內、且當下判定用的距離超過 8 yalm；另一邊 5 秒內結算同一技能的合成一筆（附上兩邊各自的時間）。
- **距王**：結算當下各自離自己那一場 Boss 的距離（顯示用）。
- **相對 Boss 相同**（機制層級）：結算當下兩人以各自 Boss 為基準的位置相距 8 yalm 內——站位不同是兩場 Boss 的位置或面向不同造成，這個機制不算站位不同。任一邊沒有 Boss 位置或面向時不判斷。

**分類**（每段只屬於一種，依序取第一個符合的；卡片標籤、距離圖顏色、摘要與建議都依這個分類）

| 順序 | 分類 | 條件 | 算站錯 | 建議 |
| --- | --- | --- | --- | --- |
| 1 | 機制不同 | 有機制不同 | 否 | 合併成一則參考 |
| 2 | Boss 無法選中 | 與無法選中時段重疊 | 否 | 合併成一則參考 |
| 3 | 可能是對稱站位 | 有對稱 | 否（可能是攻略或分配不同） | 合併成一則參考 |
| 4 | 機制 | 有結算的機制，且至少一個不是相對 Boss 相同 | 是 | 「建議」：機制結算時站位不同 |
| 5 | 相對 Boss 相同 | 有結算的機制，但全部相對 Boss 相同 | 否 | 不列出 |
| 6 | 移動路線不同 | 沒有結算的機制 | 輕微 | 持續 5 秒以上的列為參考 |

**已知限制**
- 以場地為基準的機制（塔、場地半邊、平台等）在兩場 Boss 站在不同位置時，以 Boss 為基準的距離不準；日誌看不出機制以什麼為基準，只能依兩場 Boss 是否在同一處整段切換。
- 兩場 Boss 相距剛超過 8 yalm 時也會切換，此時坦克拉怪方向造成的 Boss 面向差異會影響離 Boss 較遠的玩家。
- Boss 面向來自事件取樣，稀疏時旋轉可能有誤差。

### 名稱
- **職業名稱**一律以遊戲官方繁中顯示（例如黑魔道士、毒蛇劍士、暗黑騎士）。
- **技能名稱**以繁中顯示：優先用官方繁中；新版本 Boss 技能沒有官方繁中時，以簡中轉繁顯示（使用者決定）；都沒有時沿用英文。滑鼠停留顯示英文名稱。
- **Boss 名稱**（戰鬥名稱）以官方繁中顯示，例如呼嘯之劍；由多個 NPC 組成的名稱（如 `living liquid / liquid hand`）逐段翻譯，查不到的段落（如 Striking Dummy）保留英文。「不是同一個 Boss」的訊息也使用繁中名稱。
- **Boss 的普通攻擊**：各 Boss 專用、遊戲資料沒有名稱的普通攻擊（FFLogs 記為 Attack，例如死因）顯示為普通攻擊的繁中名稱「攻擊」。
- **道具**（例如爆發藥）同樣以官方繁中顯示，HQ 道具加上「（HQ）」，例如「3級剛力之寶藥（HQ）」。

## 建議規則

依重要性（優先／建議／參考）排序。**「優先」只放影響輸出的項目**（死亡、停手、GCD 速度、推進、技能窗口／爆發、輸出技能與爆發藥少用）；減傷、移動與站位最多到「建議」。同等級維持產生順序（死亡 → 停手 → GCD 速度 → 推進 → 冷卻技 → 技能窗口 → 開打前 → 技能 → 站位）。

| 規則 | 條件 | 等級 |
|---|---|---|
| **死亡**（永遠排第一） | 我在比較範圍內死亡：標題「你死亡了 N 次：避免死亡是最優先的改進」，列出每次的時間與致命技能、死亡到恢復行動共幾秒無法輸出、參考是否也死亡，並明確提醒「不要死亡」；「查看」跳到第一次死亡 | 優先 |
| 停手總結 | 有少打 GCD 的時段（不含 Boss 控場造成的） | 共少 ≥ 3 個 GCD 為優先 |
| 停手是 Boss 控場造成 | 標示為控場的停手合併為一則，列出時間與控場效果 | 參考 |
| 個別停手（最多 3 段） | 依參考同段 GCD 數排序；同段兩人平均距離 > 5 yalm 時補充「可能是走位路線不同」；**停手期間我已死亡時**，標題加「（這段期間你已死亡）」，說明改為死亡時間與致命技能並提醒不要死亡 | 參考 ≥ 3 個 GCD 為優先 |
| GCD 較慢 | 比參考慢 > 10 毫秒；估計整場少打的 GCD 數 | 估計 ≥ 3 個為優先 |
| **推進比參考慢** | 每次推進差距一則：「6:31.2 推進比參考慢 8.9 秒」，說明參考與我推進的時間、之後的機制都跟著延後，並建議對照之前的 GCD、技能窗口與爆發；之前有死亡時註明；我較快推進時不提 | 慢 ≥ 8 秒為優先，否則建議 |
| **DoT 覆蓋率未達目標** | 每條 DoT 一則：「X 覆蓋率 N%（目標 T%，參考 M%）」；有參考時只在我比參考低時提 | 比目標低 ≥ 10 個百分點為優先，否則建議 |
| **DoT 提早續上** | 每分鐘覆蓋掉的時間達到提醒門檻（見「DoT」）：「X 提早續上：每分鐘覆蓋掉 N 秒（參考 M 秒）」，列出覆蓋最多的 3 次，「查看」跳到最多的一次；有參考時只在我比參考多時提 | 依門檻：高為優先、中為建議、低為參考 |
| **冷卻技沒有好了就用** | 我比「最多可用」少用、且使用率比參考低：「X：最多可用 N 次，你用了 M 次（參考 …）」，列出晚了 5 秒以上的時間點（最多 3 個，依晚得最多挑選），「查看」跳到晚得最多的一次；這些技能不再重複出現「少用」建議 | 少用 ≥ 2 次為優先，否則建議 |
| **技能窗口合格率較低** | 每種窗口一則：「X：你 N 次中 K 次合格，參考 …」，列出最常見的 2 個問題與次數，「查看」跳到第一個不合格的窗口；我全部合格或合格率不低於參考時不提 | 比參考低 ≥ 30 個百分點為優先，否則建議 |
| **開打前的準備不同** | 參考開打時身上有、我沒有的自身效果（例如明鏡止水、坦姿、進食） | 建議 |
| 爆發藥少用 | 藥水使用次數較少 | 優先 |
| 輸出能力技少用 ≥ 2 次 | 參考使用 ≤ 30 次的 oGCD | 優先 |
| 輸出能力技各少用 1 次 | 合併為一則 | 建議 |
| 使用了參考沒用的 GCD | ≥ 3 次（例如武士的燕飛，代表離 Boss 太遠） | 建議 |
| 技能平均較晚使用 | 配對 ≥ 2 次、平均晚 > 5 秒 | 建議 |
| **團隊減傷／移動：參考有用、我沒有對應使用** | 參考的使用在我的前後 30 秒內沒有對應，或次數較少；列出參考的使用時間（最多 5 個），「查看」跳到第一個；團隊減傷註明「影響隊友的生存」 | 建議 |
| **團隊減傷／移動：平均較晚使用** | 配對 ≥ 2 次、平均晚 > 5 秒 | 建議 |
| **自身減傷**：少用、時機不同或較晚 | 同上；註明「只要能保住自己即可」 | 參考 |
| **機制結算時站位不同**（最多 5 段） | 分類為「機制」（見「比較規則／站位判定」）；標題指出機制名稱與時間（不含相對 Boss 相同的機制）；依是否同時少打 GCD、距離排序（同時少打的 GCD 由停手建議列為優先）；以 Boss 為基準的段註明兩場 Boss 的距離 | 建議 |
| 附近沒有機制的站位不同（最多 3 段） | 分類為「移動路線不同」、持續 ≥ 5 秒 | 參考 |
| 站位差異發生在 Boss 隨機機制不同時 | 分類為「機制不同」的合併為一則，列出時間與兩邊的機制（最多 5 段） | 參考 |
| 站位差異發生在 Boss 無法選中時 | 分類為「Boss 無法選中」的合併為一則，列出時間（最多 5 段） | 參考 |
| 可能是不同攻略 | 分類為「可能是對稱站位」的合併為一則 | 參考 |
| 輔助技能少用 | 合併為一則 | 參考 |

- GCD 技能（連擊等）的次數差是少打 GCD 的結果，已由停手與 GCD 速度涵蓋，不列為「少用」。
- 與機制差異整合：站位差異或停手時段開始前 10 秒內到結束之間 Boss 機制不同時，建議中註明（同名不同 ID 附上 ID）；該站位差異降為「參考」。
- 建議為**規則式**產生（結果可預期、不需費用）。

### 只有我的日誌時
不需要參考就能判斷的規則，依同樣的等級排序（死亡 → 停手 → 冷卻技 → 技能窗口 → 懲罰 → 強化藥）；需要比較的（GCD 速度、推進、技能次數與時機、減傷、站位、開打前）等選了參考日誌才提出。

| 規則 | 條件 | 等級 |
|---|---|---|
| 死亡 | 同上，不比較參考 | 優先 |
| 停手總結 | 有停手時段（不含控場）：「有 N 段停手，約少打 M 個 GCD」（依我的 GCD 間隔估計，已扣除 Boss 無法選中與死亡的時間） | 共少 ≥ 3 個為優先 |
| 個別停手（最多 3 段） | 依估計少打的 GCD 數排序 | ≥ 3 個為優先 |
| 停手是 Boss 控場造成 | 同上 | 參考 |
| 冷卻技沒有好了就用 | 我比「最多可用」少用（不比較參考的使用率） | 少用 ≥ 2 次為優先 |
| DoT 覆蓋率、提早續上 | 同上，不比較參考 | 同上 |
| 技能窗口不合格 | 每種窗口有不合格就一則：「X：N 次中 K 次合格」，列出最常見的問題 | 建議 |
| 被施加傷害降低 | Boss 施加的「傷害降低」（機制失誤的懲罰；衰弱等死亡的結果由死亡建議涵蓋），列出時間與總秒數 | 建議 |
| 整場沒有使用強化藥 | 沒有得到強化藥效果（含開打前） | 建議 |
